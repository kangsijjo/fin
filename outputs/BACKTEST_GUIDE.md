# Phase 2 — 백테스트 실행 가이드

데이터가 수집되고 나서 실행하는 백테스트 흐름입니다.

## 전체 파일 구조

```
[ Phase 1: 데이터 수집 ]
  config.py            ─ 룰 v2 + KIS 인증
  kis_api.py           ─ KIS API 통신
  data_collector.py    ─ 데이터 수집 메인
  run_collector.bat    ─ 자동 실행 배치
  register_task.bat    ─ 작업 스케줄러 등록
  unregister_task.bat  ─ 등록 해제

[ Phase 2: 백테스트 ]
  data_loader.py       ─ 수집된 CSV 로드
  detector.py          ─ 박스권/거래량 감지
  simulator.py         ─ 가상 매매 (모드 A/B/AB)
  analyzer.py          ─ 결과 통계/리포트
  backtest.py          ─ 메인 실행 스크립트
```

## 실행 흐름

```
data/minute_bars/*.csv
        │
        ▼
data_loader     ── 분봉 CSV를 DataFrame으로 로드
        │
        ▼
detector        ── 각 분봉에 박스/거래량 신호 컬럼 추가
        │       (is_box, box_width_pct, is_volume_surge, vol_ratio, ...)
        ▼
simulator       ── 진입/청산 룰 적용해 가상 매매
        │       3가지 모드: A, B, AB (각각 별도 실행)
        ▼
analyzer        ── 통계 산출 + CSV 저장
        │       (승률, 손익비, MDD, 종료사유 분포)
        ▼
콘솔 리포트 + results/*.csv
```

## 사용법

### 1. 모듈 단위 테스트 (데이터 형식 확인)

데이터 수집이 1~2일치라도 됐다면, 먼저 데이터 로드가 정상인지 확인:

```cmd
py -3.11 data_loader.py
```

출력 예시:
```
수집된 날짜 2개: ['20260514', '20260515']

[20260515] ranking 확인:
   rank    code  name   ...
   ...

[20260515] 모든 종목 분봉 로드:
  30개 종목 로드 완료

  [005930] 분봉 샘플:
   datetime             open   high   low    close   volume
   2026-05-15 09:00:00  72000  72100  71900  72050   53000
   ...
   총 380개 분봉
```

이게 정상 출력되면 데이터 형식 OK.

### 2. 감지 모듈 단위 테스트

```cmd
py -3.11 detector.py
```

가짜 데이터로 박스/거래량 신호가 잘 잡히는지 확인합니다.

### 3. 시뮬레이터 단일 날짜 테스트

```cmd
py -3.11 simulator.py 20260515 AB
```

특정 날짜를 AB 모드로 시뮬레이션 → 매매 내역 일부 출력.

### 4. 전체 백테스트 (3가지 모드 비교)

```cmd
# 수집된 모든 날짜 × 모드 A,B,AB 비교
py -3.11 backtest.py

# 특정 날짜만
py -3.11 backtest.py 20260515

# 특정 모드만
py -3.11 backtest.py AB

# 둘 다 지정
py -3.11 backtest.py 20260515 AB
```

### 결과 해석

콘솔에 표가 출력됩니다:

```
        label  n_trades  win_rate_pct  avg_net_pct  avg_win_pct  avg_loss_pct  profit_factor  cum_pct  mdd_pct  avg_holding_min
       mode_A        50         88.0         0.05         0.25        -1.75           1.4     2.50    -1.80              4.2
       mode_B        12         75.0         0.40         0.85        -1.85           2.5     4.80    -2.10              3.8
      mode_AB        45         86.0         0.30         0.55        -1.78           2.1     13.5    -1.90              4.5
```

읽는 법:
- **win_rate_pct**: 승률 (높을수록 좋지만 단독으로 보면 안 됨)
- **avg_net_pct**: 매매당 평균 순수익률 (양수여야 의미 있음)
- **profit_factor**: 1.5 이상이면 양호, 2.0 이상이면 우수
- **cum_pct**: 매매당 net_pct의 단순 합 (매매 효율의 척도)
- **mdd_pct**: 누적 손실 최대 구간 (-가 작을수록 좋음)

`results/trades_AB_*.csv` 를 열면 매매 한 건 한 건의 상세를 볼 수 있습니다.

## 시뮬레이션 모델의 한계

코드 짠 사람이 솔직히 짚어둡니다:

### 1. 분봉 단위 시뮬레이션

- KIS API가 1분봉까지만 제공해서, 1분 안의 가격 움직임은 알 수 없습니다.
- "이 분봉의 high가 익절가에 닿았는가" 식으로 보수적으로 체결 판정합니다.
- 같은 분봉에서 익절가와 손절가가 모두 닿으면 **손절을 우선** 적용 (worst case).
- 실전은 이보다 약간 유리할 가능성이 있습니다.

### 2. 호가/슬리피지 가정

- "박스 하단 +5틱" 을 "박스폭의 5%" 로 근사했습니다.
- 슬리피지를 매수/매도 각각 0.05%로 가정 (`config.py`에서 조정 가능).
- 실전에서 호가 잔량이 얇으면 슬리피지가 더 클 수 있습니다.

### 3. KOSPI/KOSDAQ 구분

- 종목별 시장 구분 정보를 따로 받지 않아, **모든 종목을 KOSDAQ(거래세 0.20%)** 로 가정.
- KOSPI 종목은 실제로 거래세 0.18%라서 약간 더 유리합니다.
- 결과는 보수적으로 나오는 셈.

### 4. 거래량 순위의 시점

- 우리가 수집하는 ranking은 "장 마감 시점의 누적 거래대금" 기준입니다.
- 본인 매매 시점("장 시작 시 상위 30") 과는 약간 다를 수 있습니다.
- 영향은 크지 않을 것으로 보지만, 인지하고 있어야 합니다.

### 5. 신호 감지 시점

- 본인은 실시간으로 1분 안의 거래량 급증을 30초 만에 봤을 수 있습니다.
- 백테스트는 1분이 끝나야 그 분의 거래량을 알 수 있습니다.
- **결과적으로 백테스트 결과는 실전보다 약간 보수적**일 가능성이 큽니다.

이 한계들 때문에:
- **백테스트가 +라면 실전은 더 +일 가능성**
- **백테스트가 -라면 실전도 -일 가능성** (자동매매 진행 안 하는 게 맞음)

## 룰 조정

`config.py` 의 `RULE_V2` 값을 바꾸고 `backtest.py` 를 다시 실행하면 됩니다.
예를 들어 거래량 급증 기준을 2.5배로 올려보고 싶다면:

```python
"volume_surge_multiplier": 2.5,  # 2.0 → 2.5
```

여러 값을 비교하고 싶다면 `backtest.py` 를 여러 번 실행하거나, 추후에 그리드 서치 모듈을 추가할 수 있습니다 (Phase 3 이후).
